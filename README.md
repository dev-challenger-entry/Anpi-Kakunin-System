### **概要**



本プロジェクトでは、Webアプリ開発の手順をあとから復習できるように、こまめにコミットをおこないます。  
学習目的でGitを活用するため、なるべく、『エラーが起きた場合もどんな問題が起きてどんなエラーを解決できたのか』という記録を残しつつ進めていきます。
  
**本プロジェクトはAI駆動開発（AI-Driven Development）で進めています。**  
設計・実装・デバッグの各工程で生成AI（Claude）を活用し、AIとの対話を通じて仕様の整理や実装方針の検討、エラーの原因調査などを行いました。  
一方で、要件定義やアーキテクチャ判断（例：Controller層はDTOのみ扱う、Entity/DTO変換はService層に限定する等）は自分自身で意思決定し、AIの提案を鵜呑みにせず検証・修正を重ねています。

  
### **本学習を通して作るもの**

災害時に、安否報告・集計を行うための企業向け安否確認システムです。

  
#### なぜ、今、安否確認システムを作るのか

緊急事態であればあるほど、電話を使ったコミュニケーションが常識です。しかし、そのとき、必ず相手が電話を取れるとは限りません。

LINEやメールも代替手段になりますが、私用の連絡に埋もれてしまう可能性があります。また、携帯電話を2台持つ方法もありますが、災害時に必ず両方を手元に置いているとは限りません。

そこで、スマートフォン1台だけで会社への安否報告を完結でき、私用の連絡に埋もれない仕組みが必要だと考えました。

さらに、災害時は焦りや混乱も想定されるため、操作性はできるだけ簡潔であるべきだと考えました。

そのため、本プロジェクトでは「迷わず、素早く、確実に」を軸に、必要な機能に絞った企業向け安否確認システムを開発していきます。



### **設計思想**



１．災害時のアクセス集中を考慮し、必要以上に複雑化させず、データベース構造もシンプルな構成を意識します。  
２．安否確認アプリにおいて、余計な装飾は不要。シンプルを突き詰めて、説明書が不要なデザインを目指します。  
３．「何を追加するか」だけでなく、「何を削るべきか」も意識し、必要な機能に絞った設計を行います。



**キャッチコピー**は、「迷わず、素早く、確実に」



###### ユーザーゴール

災害発生時、社員が迷うことなく安否状況を報告できることを目指します。

ログインから安否状況の登録までをシンプルにし、緊急時でも必要な操作を素早く完了できるようにします。



###### **ビジネスゴール**

管理者が社員の安否状況を一覧や集計結果から迅速に把握し、会社全体の状況を確認できることを目指します。

報告状況をもとに、必要な社員への対応や、その後の会社運営に必要な判断につなげられる仕組みを提供します。

### **セットアップ手順**

&#x20;  事前にインストールが必要なもの(Windowsを想定したセットアップ手順)

* Git
* Java（本プロジェクトではJava 21を使用）
* Node.js
* MySQL

　　MySQLをインストールしたあと、MySQLのbinフォルダを環境変数Pathに追加してください。

　　また、MySQLのインストール時に設定したMySQL Root Passwordを控えておいてください。

　　本プロジェクトでは、Spring Boot起動時にcompany\_systemデータベースが存在しない場合、自動的に作成される設定にしています。

&#x20;

１．git cloneしてこのリポジトリを手元のパソコンに取り込みます。

　　その後、.env.exampleファイルを同じ階層へコピーして、拡張子を削除。.envという名前のファイルを作ってください。

　　作成したファイルの中の項目に、ご利用環境のMySQLのパスワードを入力してください。

&#x20;

２．次に、Windows環境なら、コマンドプロンプトを立ち上げます。  
　　package-lock.jsonがあるフォルダのパスを確認してください。次はディレクトリ移動します。

&#x20;   cd C:\\\\Users\\\\user\\\\OneDrive\\\\Desktop\\\\Anpi-Kakunin-System\\\\my-react-app



　　※もしcloneした場所が、パソコンを起動してログインした後に表示される最初の画面であれば  
　　コマンドプロンプトには【cd C:\\Users\\user\\OneDrive\\Desktop\\Anpi-Kakunin-System\\my-react-app】と書き込みます。

&#x20;   ※C:\\Users\\user\\...の部分は、ご自身のパソコンの環境に合わせて変更してください。

&#x20;

３．npm installと入力してください。

&#x20;

４．Javaのメインクラスを実行して、Spring Bootを起動します。

&#x20;    起動と同時に、Reactも起動する設定になっています。

&#x20;    これで、バックエンドとフロントエンドの両方が起動します。



**初期アカウントについて**

&#x20;    SetupDefaultPasswords.java に初期アカウントのIDとパスワードを記載しています。

&#x20;    アプリの初回起動時に、設定した初期アカウントが登録されます。

&#x20;   ※初期パスワードは、ログイン後に管理者アカウントから変更できます。

###### **初期設定で選択した依存関係**

|ライブラリ|役割|
|-|-|
|Spring Web (spring-boot-starter-web)|ブラウザからのアクセスを受け付け、Webアプリを動かすための基本機能|
|Thymeleaf (spring-boot-starter-thymeleaf)|Javaのデータを画面（HTML）に表示させる仕組み|
|Spring Boot DevTools (spring-boot-devtools)|コード変更時にアプリを自動で再起動してくれるツール|
|Lombok (lombok)|Getter/Setterなど、長くなりがちなコードを省略して書けるライブラリ|



※ Thymeleaf（spring-boot-starter-thymeleaf）は、開発中に、フロントエンドを介さずURLへ直接アクセスされた場合でも、ログイン状態や権限によってアクセスを制御できるかを検証するために使用しました。



**環境変数**  
git clone後のローカル環境でのテストの際は、ご利用環境に応じて.envを作成し、設定してください。
テンプレートとして、.env.exampleを用意してあります。
